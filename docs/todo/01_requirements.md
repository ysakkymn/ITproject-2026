# TODOアプリ 要件定義書 (V1)

## 1. 目的・対象範囲
本要件定義は、Express + TypeScript + EJSを用いた既存のWebサイトに、シンプルで一般的なTODO管理機能を追加するためのV1要件を定義するものです。
対象範囲は、画面（`/todo`）からの操作および、それに紐づくREST API（`/api/todo/v1/todos`）の基本CRUD機能（一覧取得、登録、完了状態の更新、削除）となります。
なお、認証機能、優先度、高度な絞り込み、タイトルの一括更新等はV1では対象外とします。

## 2. 4機能と受け入れ条件

### REQ-01: TODO一覧取得
- **操作:** `/todo` 画面へのアクセス時、または画面ロード時にバックエンドからTODO一覧を取得・表示する。
- **入力:** なし（GETリクエスト）
- **結果:** 登録されているTODOの一覧を返す。0件の場合はステータスコード `200` で `data: []` を返す。
- **エラー:** 500（サーバーエラー）、503（DB接続エラー等）
- **受け入れ条件:** データベースに登録されている全件のデータが正しく取得できること。
- **確認方法:** `/todo` にアクセスし、登録済みのTODOが一覧として画面に表示されることをブラウザで確認する。

### REQ-02: TODO登録
- **操作:** 画面上の入力フォームにタイトルを入力し、登録ボタンを押下する。
- **入力:** `title` (前後の空白を除いて1〜100文字の文字列)
- **結果:** 新しいTODOを作成し、ステータスコード `201`（または `200`）と作成されたTODOデータを返す。初期状態の完了フラグは `false`。
- **エラー:** 400（不正なリクエスト）、422（バリデーションエラー：文字数オーバーや空文字など）、500、503
- **受け入れ条件:** 条件を満たすタイトルであれば正常に保存され、一覧に即時反映されること。
- **確認方法:** フォームに文字を入力して登録し、エラーなくリストに追加されることを確認する。

### REQ-03: TODO完了状態の部分更新
- **操作:** 一覧内のチェックボックスをクリックし、完了・未完了の状態を切り替える。
- **入力:** 対象のID（1以上の整数）、更新する完了フラグ等のパラメータ（PATCHリクエスト）
- **結果:** 指定したTODOのステータスを更新し、ステータスコード `200` と更新後のデータを返す。
- **エラー:** 400、422（IDが不正など）、404（存在しないID）、500、503
- **受け入れ条件:** 該当するIDのTODOの完了状態のみが部分的に更新されること。
- **確認方法:** チェックボックスのON/OFFを切り替え、状態がデータベースおよび画面上で変更されることを確認する。

### REQ-04: TODO削除
- **操作:** 一覧内の削除ボタンをクリックする。
- **入力:** 対象のID（1以上の整数、DELETEリクエスト）
- **Result (結果):** 指定したTODOを削除し、ステータスコード `204`（No Content）で本文なしを返す。
- **エラー:** 400、404（存在しないID）、500、503
- **受け入れ条件:** 該当するIDのレコードがデータベースから完全に削除されること。
- **確認方法:** 削除ボタンを押した際、該当項目が一覧から消え、再読み込みしても復活しないことを確認する。

## 3. 共通のデータ・エラー条件
- **データ仕様:** 
  - `id`: 1以上の整数（自動採番）
  - `title`: 1〜100文字（前後の空白トリム済み）
  - `completed`: 真偽値（`true` / `false`）
- **成功レスポンス共通フォーマット:** 
  ```json
  {
    "success": true,
    "data": ...
  }

  {
  "success": false,
  "error": {
    "code": "エラーコードまたはステータス",
    "message": "エラーの詳細メッセージ"
  }
}
